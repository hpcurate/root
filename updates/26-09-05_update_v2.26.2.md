## What was done

### The shadow needs room (task 3)

The offset is its own token now: `--title-sh-x`, with `--title-sh` built from
it. That is the whole fix, and it is a token rather than a repeated literal for
a specific reason: **a thing that clips has to reserve exactly as much room as
the shadow takes**, and two numbers that have to agree should be one number.

`.h-daynum` clips on purpose — that is what stops a number on its way out of the
shuffle making the row taller. The shadow is the one part of the glyph that
sticks out to the right, so it was precisely the part being cut off. The box is
a shadow-width wider (`min-width:calc(1.1em + var(--title-sh-x))`) and the
digits sit a shadow-width off its right edge, so the clip still catches the
outgoing number and no longer catches the shadow.

STORE's total reserves the same with a `padding-right`.

### The dot is the inverse of the word (task 2)

`DO<em>.</em>`. The word is title-coloured with an accent shadow. The dot is
already the accent, so it was an accent shape behind an accent shape — not a
shadow at all, just a slightly fatter dot with a soft right edge.

`.h-logo em` takes `--title-sh-c: var(--tx)`: accent glyph, title-coloured
shadow. Exactly the request, and it reads as the same treatment seen from the
other side rather than as an exception. `text-shadow` is inherited, so the rule
only has to restate the colour.

### STORE's total flashes as one object (task 1)

The `€` sat at a fixed accent while the digits went green and red. Half a number
changing colour reads as a rendering fault rather than as a signal, which is
what "make shadow and € symbol also change" is describing.

- `.h-cost.up .cu` / `.h-cost.down .cu` take the flash colour **and** set
  `--title-sh-c` to it, so the mark and both shadows move together with the
  digits.
- The mark also gained the shadow it had been opted out of. That exemption was
  written in 2.25.1 because at `.4em` the then-unrounded `.055em` came out
  sub-pixel and doubled into mush — the same defect 2.26.1 fixed everywhere
  else. With a whole-pixel offset there is nothing left to avoid.
- At rest it wears the shadow **inverted**, like the wordmark's dot: accent
  glyph, title-coloured shadow. An accent mark with an accent shadow would have
  been invisible, which is the same mistake task 2 is about.

### DO's QUICK heading (task 4)

**It has no shadow.** `.tt-name` was declared twice in `do.css`:

```
line 201  .ns-do .tt-name{…font:inherit…}          QUICK's fold button
line 230  .ns-do .tt-name{font:400 12.5px/1.4 …}   a task row's name
```

Same specificity, and the row's rule is written later, so it won every time.
QUICK's heading had been set in a task row's font — 12.5px mono in the
foreground colour — while BLOCKS, TODAY and MEDIA used the section head's own
10px letter-spaced accent caps. That difference is what read as "it seems like
it has the shadow too".

The two names had nothing to do with each other and only ever collided. The fold
button is `.tt-fold` now, `.tt-name` unambiguously means a task row's name, and
a check fails if either is ever declared twice again.

**Decision made on Hugo's behalf:** renaming rather than reordering. Moving the
rule below its collision would have worked and left the trap in place.

## Notes

Three of these four are consequences of the shadow itself, which is what
happens when a treatment designed against one element (STORE's 54px total) is
put on everything else in two releases. The token is doing better now: the
offset is named, so the two places that have to reserve it read the same value,
and the inversion rule — accent glyph gets the title colour, title glyph gets
the accent — is now stated in two places rather than invented twice.
