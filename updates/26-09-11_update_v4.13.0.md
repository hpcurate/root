## What was done

### A journal under everything (`js/sync.js`)

The engine was a list of keys this file knows about. "Anything I do should be
kept and then synced" cannot be answered by a list, and neither can "the most
recent is used" — no record carries a timestamp.

So `sync.js` now wraps `Storage.prototype.setItem` and `removeItem` **once**, at
load, and notes `key → moment` into a new `root_sync_touch_v1`. No app reports
its own writes and no app knows this happened, which is the rule §10 has always
had: sync belongs to the shell. Sync's own three keys are skipped — a journal
that journals itself never settles — and the index is written on a one-second
debounce plus a `pagehide` flush, because ticking a routine is a dozen writes and
one change.

Everything else here is downstream of that.

### Everything changed in the last 24 hours travels

A payload now carries the route's own list **plus** every key touched inside
`SINCE_MS` (24h, a constant rather than a dial — a window you can shrink is a
window that quietly stops carrying things). The old list stays as the floor, so
an install whose journal is empty syncs exactly what it used to, and a key
nothing in this file has ever heard of is carried because it was written.

`plan()` merges whatever the payload actually contains rather than walking a
fixed list, which is the other half of the same idea.

### The more recent write wins

Each record's moment travels beside it as `touch`, so both devices compare the
same two numbers. `mergeState` takes the newer one; equal-and-different is still
the only thing that opens the overlap sheet. The structural merges that were
already better than a timestamp are untouched — LOG per half, blocks and entries
unioned, DO's ticks unioned, DAY by its own `written`.

One subtlety worth naming: `commit()` re-stamps a record it took from the other
device with **that device's** moment, not with now. Otherwise the next sync would
see a record this device had "just written" and hand it back.

### One tap, and it knows which direction

`SYNC.run()` reads the Todoist route, merges what is new, then sends back what
this device holds afterwards — the only safe order, and why the button says
`sync`. **DO's header button is now this.** Decided on Hugo's behalf: that button
used to run DO's own Todoist routine sync, which keeps its `sync now` button
under settings → do. The alternative was a second button in a header with room
for one.

A run that hits a real tie does not guess: it hands the plan back and the
overlap sheet opens, and the push waits until the question is answered.

### An id, so an import that has already happened is free

Every payload carries `id`, a digest of its contents — not of who wrote it or
when. Push records it, import records it, and the next run compares one string
instead of planning a merge across twenty days. It is also what stops two devices
on a timer from trading the same bytes forever: an unchanged board builds the
same id, and a push whose id was already sent is not sent at all.

### The SYNC section (`index.html`, `js/settings.js`)

A fourth category beside **apps**, **appearance** and **data**, exactly as asked.
It carries the one button and when it last ran, the refresh dial, safe transfer,
the window dial, the four what-travels switches, and the three routes — which
moved out of `data`, leaving a line there pointing at where they went.

- **Refresh frequency** — the nine intervals asked for, plus **off**, which is
  the default. The request did not ask for an off; a background sync nobody chose
  is the reason it is there, and §10's "both are manual" was a real rule that
  this update is allowed to relax only because the merge stopped asking
  questions.
- **What travels** — `apps` (everything an app wrote), `settings` (the content
  layer), `style` (the whole appearance engine), `system` (the tab you were on,
  the label cache, the sync stamps). System is off: it is the one group where the
  other device's answer is not better than this one's.
- **Safe transfer**, on — the old private/not-private route split made into a
  dial. On, the Todoist route leaves `log_*`, `capTracker.*` and `store_state_*`
  behind; off is how the logged day goes over Todoist. Tokens are not part of the
  deal: `plan_token` and `root_todoist_v1` travel on no route, by no switch.

## Verification

`node test/update.mjs check --full` — **1221 harness checks, 0 failed**, syntax
across 20 files, the boot smoke (10 apps, 15 themes, 15 panels) and the runner's
own 6 tests.

29 of those checks are new, covering what actually changed:

- a write to a key nothing in `sync.js` knows about is journalled, is inside the
  24-hour window, and turns up in the payload with its moment beside it
- sync's own bookkeeping keys are never journalled
- the four groups map the keys the section says they do; a group switched off
  carries nothing; `system` is off until asked for
- safe transfer keeps `log_*` off Todoist and lets it through when turned off,
  and the logged day then appears in the payload beside DO's
- token-only keys travel on no route either way
- the newer record wins, ours is kept when ours is newer, the same moment is
  still a question
- a later record from the other device is planned as a write rather than a
  question, is committed, and the journal keeps **their** moment
- two builds of an unchanged device share an id; `alreadySeen` flips only after
  the import is recorded; a changed device builds a different id
- the section carries the refresh dial, safe transfer and the four switches, the
  dial offers `off` plus the nine intervals, and DO's header button calls
  `SET.syncNow`

Two existing checks were updated rather than worked around: the settings home now
lists four categories, and the routes check opens the `sync` panel.

**Not verified:** anything that needs two real devices and a real Todoist
account. The transports were already outside the harness (`pushTodoist` needs the
API, the file route needs a picker), and `SYNC.run()` sits on top of both, so the
round trip — push from one device, tap sync on the other, watch the id stop it
from importing twice — has been reasoned through and tested at the merge, not
observed. The timer itself is likewise untested: it is `setTimeout` around the
same `run()`. Nothing visual was checked; jsdom cannot.
