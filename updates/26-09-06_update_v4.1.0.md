## What was done

### CREATE · the strip, and a fourth chip on it

`index.html`, `js/create.js`, `css/create.css`. The area filter is DO's
DAILY / MEDIA / OTHER selector: one bordered rail, flat chips inside it, and a
glider that slides under the live one. The session log's own filter — which was
a second, different control doing the same job — is now the same strip from the
same builder.

It differs from DO's in exactly one way, and that is written into the sheet:
DO's lives in the title band, so its height is `--band-row` and its chips are a
fixed 32px; CREATE's lives in the content and takes its height from its own
padding. **The shape is now written twice**, in `do.css` and in `create.css`.
ROOT.md §6 names the pair so a change to one is known to be a change to both —
promoting it to a shared shell class would have meant refactoring DO's band
strip, which is load-bearing in a way this batch had no reason to disturb.

**CURATE** is the fourth chip. Every open Todoist task carrying
`create.curate.label` (`@curate`), grouped under the section it sits in, in
Todoist's own order: project order, then section order, then the task's own
order inside its section. Three calls — the label query, `/projects` and
`/sections` — rather than one per project. A task with no section gets its
project's own unsectioned group, which sorts above the sections, because that
is where Todoist itself puts it. Cached in `create_v1` so the tab draws before
the network answers, refreshed behind that when it is older than the window,
and refreshable by hand.

**Decision made on Hugo's behalf, and it is a real one:** the module's own
header said "no network at all", and this ends it. What is built is the
narrowest version that answers the request — the tab **reads and never writes**.
CREATE does not close, move, reschedule or create a task: closing a curate task
is DO's job, filing one is PLAN's, and a third app with an opinion about the
same list is how two of them end up disagreeing. The module header, the settings
panel and ROOT.md §6 all say so, and two harness checks hold the line: no
`fetch(` and no `api.todoist.com` in the module, and no `Todoist.call(`, no
method, no `/close`, no `/reopen`.

### CREATE · a mix has no key

`js/config.js`, `js/create.js`, `js/settings.js`, `css/settings.css`. An area
carries `fields` — which of the three meta chips its work asks for. Production
asks for tempo, key and tags; mixing asks for tempo and tags, because a DJ set's
key changes every four minutes and the field was asking a question with no
answer.

Switching a field off takes away the chip **and** its handler, so there is no
hidden button with a live editor behind it, and it never touches what is already
written: the value stays in the record and comes back the moment the field is
switched on again. That is exactly the rule `log.fields` has followed since 2.0.
The area editor gained a checkbox per field, read back with the rest of the tree.

### CREATE · the spacing, and what it actually was

`index.html`, `css/create.css`. Two things, and the first is the interesting one.

**`#cr-hero` and `#cr-sorts` had rules written for `.cr-hero` and `.cr-sorts`,
and neither class was ever in the markup.** So the shelf's big number was never
centred and never had its margins, and the sort chips were never a flex row with
a gap in them or a sideways scroll — for two whole versions. That is what "the
spacing is off" turned out to be. Fixed, and a harness check now asserts every
generated block on that screen carries the class its rules are written for.

Separately, every literal pixel margin, padding and gap in `create.css` became a
ratio of `--dens`. The Spacing dial moved every pad on the page and left the
gaps *between* the sections exactly where they were, so the screen got denser
and looser at the same time — which is the other half of what "the spacing is
off" looks like. ROOT.md §4 has required this since 2.0; this sheet had drifted.

### CREATE reaches LOG

`js/create.js`, `js/log.js`. `CREATE.dayStats(iso)` and
`CREATE.rangeStats(days)` are synchronous readers over `create_v1` — the same
shape `TRACK.doneOn` and `LEARN.dailyStats` already have, and LOG stores nothing
of CREATE's: it asks at note time and at report time.

The note gains a `#### create` section on a day with sessions — `create_hours`,
`create_sessions`, `create_areas`, `create_works`, `create_did` — and the parser
reads it back into `d.c`, beside `d.s`. Both reports gain an "at the desk" row
in habits and a `## create` section with the hours split by area and what was
worked on. A report built from pasted Obsidian notes on another device gets the
hours from the parsed rows; one built here gets them from CREATE directly.

**The rows are additive, which is what keeps the export a contract:** a day with
no sessions has no section at all, and the Obsidian parser looks rows up by name
and ignores the ones it does not know. Same rule the `cap_topics` / `anki_rated`
study rows have followed since 2.3.

### The undo pill

`index.html`, `css/tokens.css`, `css/shell.css`, `js/prefs.js`, `js/shell.js`,
and seven modules. Clearing is the destructive act you do on purpose and still
regret, so it does not toast any more: `Shell.undo(label, restore)` puts up a
pill with the way back in it.

- **Where it is offered:** STORE's list, its cart counter and its trip history;
  PLAN's queue and its sent history; DO's day; LOG's day, its caffeine counters
  and its curate counters; DAY's stored days and one day; TRACK's ticks;
  CREATE's shelf. A harness check fails if one of the seven modules stops.
- **How long:** a new `undoSec` dial under behaviour → Safety, default **5s**,
  as asked. `0` pins it until it is tapped or the next clear replaces it.
- **What it wears:** the title. `800 12px/1 var(--head)` with
  `text-shadow:var(--title-sh-x) 0 0 var(--title-sh-c)` — composed at the point
  of use, never through a token that pre-resolves its colour (ROOT.md §6). The
  arrow is a new `#ico-undo` sprite symbol rather than a typed character, and it
  takes the same offset as a `drop-shadow()`, which is the one filter that is
  the same effect on a stroked path.
- **It replaces the toast rather than joining it.** They occupy the same spot,
  and "list cleared" said twice in two shapes is one message too many.
- **Nothing about it is stored.** The restore is a closure over what was already
  read, so the way back lives exactly as long as the pill does. An undo that
  survived a reload would be an edit history, which this is not.

### The navigation arrows

`css/log.css`, `css/plan.css`. LOG's date arrows and PLAN's day stepper are the
same control doing the same job, and they were thin mono glyphs sitting a few
pixels under a heavy display wordmark. They are the display face at the
wordmark's weight, in title ink, with the title's hard offset copy behind them.

**Written into the sheet as a caveat:** `←` and `→` are typed characters, so
whichever face `--head` resolves to may not carry them and the browser will fall
back per glyph. The weight, the ink and the shadow all still land — those are
not the font's to refuse — but on a display face with no arrow, the glyph itself
is the fallback's. DAY's stepper solved that in 2.21.2 by drawing its arrows
from the sprite; these stay typed because what was asked for is the title's
*treatment*, and an icon cannot wear a text-shadow.

### LOG · the evening's blocks

`index.html`, `js/log.js`, `css/log.css`. **Planned in PLAN comes first** and
the nine standing blocks moved under it, folded away behind a tap. Closed by
default, as asked — and it opens itself if one of the standing blocks is already
ticked, because a tick you cannot see is worse than a long form. Not stored:
"default hidden" is the ask, and every evening starts from the same place.

**And the two strips stopped lighting each other.** `e.blocks` is a flat list of
names and the Obsidian side parses that shape, so it stays one — which means it
cannot say *where* a name was ticked, and a planned task called "mixing" and the
standing block called "mixing" are the same name. `e.blocksPlan` is the marker
that separates them: the subset of `e.blocks` ticked on the planned strip. It is
UI state — never exported, absent on every day written before 4.1 (which reads
as all-own, which is what it was), and emptied by the note parser.

**Decision made on Hugo's behalf:** a name is still in the record only once, so
ticking it on the *other* strip moves which chip is lit rather than counting it
twice. The day is a record of what was done, and "mixing" done once is one block
however many places offered it. A block ticked on DO's today list arrives on the
planned strip, since that is where DO's tasks are drawn.

### LOG · the fortnight is six charts

`js/log.js`, `css/log.css`. Tapping the key row underneath moves to the next
chart. The plot itself still opens over the month, on every one of them — the
two controls are two elements rather than one with a corner in it, because the
small chart is 58px tall and a third thing to aim at in there is not a control.
The opened chart carries a "close" in its corner where the key row used to say
it, since the key row now names the chart.

Six, all read from fields the day record already holds:

| | series |
| --- | --- |
| the day | energy · mood · stress (1–5) |
| morning vs evening | energy am/pm, mood am/pm (1–5) |
| sleep | hours slept, the hour you woke (hours) |
| walking | morning km, evening km (km) |
| output | blocks, mix, prod, cont (counts) |
| intake | coffee, energy drinks, meals (counts) |

**One unit per chart, always.** A shared y-axis is a claim that two numbers are
comparable, so hours never share an axis with counts and counts never share one
with a 1–5 answer — which is why there are six charts rather than two crowded
ones. Each takes its own scale, and the gridlines and the axis labels come from
one call so an axis that is 0–8 kilometres cannot end up with lines in one place
and numbers in another. A chart with nothing in it is dropped from the cycle
rather than shown empty.

A 0 only counts on a half of the day that was actually logged — `caf_c` is 0 in
every fresh record, so without that a fortnight of untouched days would draw a
confident flat line along zero.

The series colours moved out of the stylesheet: `log.js` writes each one onto
its own `<g>` as `--s-c` and the sheet has one rule per shape, so a seventh
chart costs no CSS. They are still literal hex, which was the point — three or
four lines have to stay apart in every one of the fifteen themes.

### PLAN · the clipped descenders

It was still not looked at, so **the task stays open** — see *Deferred*.

### A real bug, caught by `test/peek.mjs`

The sleep chart read a wake-up time through a `hourOf()` that already existed in
`log.js` for the alert rules and answers **minutes since midnight**, not hours
of the day. Two `function` declarations of one name in a module is the later one
winning, silently: nothing complained, no check failed, and the chart reported
an average wake-up of 441. Renamed to `wakeHour`, and there is now a harness
check over every module for a duplicate top-level declaration. ROOT.md §6
carries it, because it is the shape of mistake any file this long can make.
