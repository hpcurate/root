## What was done

**PLAN — the Block row is numbered, and fills itself** (`js/plan.js`). It was b1 · b2 · b3, picked by hand for each task.
- A new task takes **the day's next block**: one more than the highest number that day's tasks hold, queued or already sent
  (`nextBlock`). So the first task for a day is block 1, the next 2, then 3 — in the order they are planned.
- The chips read **1 2 3 4 5 6** (at least `log.maxBlocks`, more if a day goes past it; `blockChoices`), each in its label's
  Todoist colour, as before. Another chip changes it; the picked one tapped again clears it (no block).
- A number nobody chose **follows the date** (← → on the form: tomorrow starts at 1 again); one changed by hand stays.
- The queue and the sent list say **"block 2"**, not "@b2".

**DAY — the schedule takes them by number** (`blocksFor`): block 1 first, then 2, 3…; the same number twice in the order they
were queued; a task with none after them.

**The labels stay** `b<number>`: what goes to Todoist is still `@b1`, `@b2`…, so nothing downstream changes meaning.
`plan.blocks` (the labels the form knows) is now b1…b6, and **DO** counts b1…b6 as blocks whatever `plan.blocks` lists, so a
day's block 4, 5 or 6 shows as a tile too, and in "→ tomorrow".

Decided on Hugo's behalf: every task gets a block (his "every block"), clearable with a tap; the number continues after the
day's sent tasks too, not only the queued ones, so a second round of planning the same day goes on from where the first
stopped.
