## What was done

### The blur — it was Interface scale (task 1)

`html{zoom:var(--ui-scale)}`. Hugo found it by moving the dial.

Document zoom multiplies every length in the page by a fraction. The app's type
is written in whole pixels — 8, 9, 9.5, 10, 11.5, 15, 54 — so at any scale but 1
every one of those becomes a fraction, and a fraction of a CSS pixel is a
fraction of a *device* pixel at any DPR. The glyphs are resampled rather than
drawn, and the smallest type suffers most. That is precisely the observed
symptom: the band's 10px date line soft, the 54px wordmark beside it sharp.

**Why four correct fixes changed nothing.** A document-wide zoom sits above
every one of them:

| Release | Found | Real defect? | Could it have been the blur? |
| --- | --- | --- | --- |
| 2.24.0 | fractional wordmark → `--title-px` | yes | no — zoom re-fractionalises it after |
| 2.24.1 | fractional safe-area inset → `--sat` | yes | no — same |
| 2.25.0 | `-webkit-overflow-scrolling` under the band | yes | no — not a compositing issue |
| 2.25.1 | `black-translucent` status bar | yes | no — not an overlay |
| 2.25.2 | `--mu` used as a label colour | yes | no — a real contrast bug, but not this |

All five were genuine and all five are kept. None is reverted.

**The dial is removed rather than tuned.** No arrangement of steps is sharp: for
a 9.5px label to land on a whole device pixel at 3× DPR the scale would have to
be a multiple of ⅔, which is not a usable dial. Keeping it would mean keeping a
control whose only effect at any non-default value is to soften every glyph in
the app.

What it was for is already covered by three controls that are whole-pixel by
construction: **Spacing** (`--dens`), **Title size** and **Sub-screen title
size**.

**An install that had moved it keeps the size it chose.** `foldAwayUiScale()`
multiplies the stored scale into Spacing, clamps it to Spacing's own range,
snaps it to Spacing's step, and deletes the key — so it runs once and a later
Spacing change is never multiplied by it a second time. `tokens.css` carries the
whole account of why the zoom is gone, so it does not get re-added by someone
reasonably thinking a UI-scale control ought to exist.

**Decision made on Hugo's behalf:** removing the dial outright rather than
leaving it at a fixed 100%. A control that can only be moved into a bug is not a
control.

### LOG — the caffeine counters had a frozen accent (task 2)

`.caf-b.on .cnt-l` was `rgba(167,139,250,.6)` — VOID's violet, written in as a
literal at 1.0 and never revisited. On every preset except VOID the label under
a selected coffee or energy drink stayed violet while its own border and its own
number had already gone to the theme's accent, which is exactly what "not
properly the selected tint when selected" describes.

It takes `var(--y)` with `opacity:.6` now — the same shape the currency counters
two rules below had always used correctly.

### The title shadow, shared (tasks 4 and 6)

It started on STORE's running total in 2.25.1. It is one token now:

```
--title-sh-c: var(--y);
--title-sh: .055em 0 0 var(--title-sh-c);
```

Worn by every sticky sub-screen title (`do`, `learn`, `log`, `plan`, `settings`,
`store`) and by the big dates on LOG and DAY. Measured in `em`, so it scales
with whatever it is applied to rather than needing a value per size — which
matters now that the sub-screen titles have their own size dial.

STORE's total keeps its ability to recolour the shadow with the number as it
rises and falls; it just sets `--title-sh-c` instead of owning the whole offset.
Three copies of the same offset in three stylesheets would have been three
chances for them to drift.

### STORE — the total's size and its currency mark (tasks 3 and 5)

Size is `min(var(--title-px), 14vw)`: exactly the wordmark's size at the default
title setting, as asked, giving way only at the largest title sizes where it
genuinely would not fit beside `STORE.` — which keeps 2.25.1's "cannot go out of
screen" true without contradicting this task.

The currency mark reads in the accent rather than muted grey.

## Verification

New coverage: no `zoom` and no `--ui-scale` anywhere in the sheets; the dial gone

pinned inline values that are now shared tokens, and the behaviour each was
guarding is still asserted.

## Notes

Five releases and four wrong answers before Hugo found it himself by moving one
dial. The signal that should have redirected the search much earlier was not any
detail of the screenshot — it was that four independent, correct, well-argued
fixes each produced *literally no change*. That is not four unlucky guesses; it
is evidence that the cause sits above everything being changed. A document-wide
zoom is exactly such a cause, and "what applies to the entire document at once"
was the question worth asking by the second report rather than the fifth.
