## What was done

### DO — six routines, by what they are for

`routinep1…p4`, `cooldown` and `cleanup` are replaced by **fix**, **fit**,
**log**, **eat**, **reset**, **plan**, with the items the brief lists, verbatim
and unglyphed. The `daily` tab carries the six; `deepclean` is untouched under
`other`.

The labels are the words themselves because DO's routine sync matches a Todoist
task on the routine's key *or* its label (`tdRoutineBySlug`) — the brief's "lists
tasks are already in todoist with the corresponding name" is what makes that
matter.

**The history survives, and that is not luck.** `do-stats-v1` holds one row per
day, `{ routineKey: [done, total] }`, and `statsFor()` sums whatever keys the
stored row has rather than the routines that exist now. A day recorded under the
old six therefore still reads in the consistency strip at exactly the percentage
it always did. There is a check for it.

**The override trap, and the migration for it.** A Config override wins for its
whole branch, and the settings editors write the whole branch on any edit — so
on any install where a routine had ever been edited, a *replaced* default would
have been invisible. `Config.migrate()` now runs at load and drops a
`do.routines` or `do.tabs` override that is **still the set it replaces**. One
renamed routine, one added item, and the keys still match: that is the same set,
edited, and the brief replaced it. A routine of your own making is a seventh key
and means hands off. `Config.load` is exported so the migration is testable
without a page reload.

### LOG — an entries switch on the month

The month grid's head grew a small `entries` button. Pressed, every cell shows
how many journal entries that day holds instead of its date; a day with none
shows nothing rather than a `0`, because a month of zeroes is a month of noise.
Not stored, deliberately — like the fortnight chart, it is a way of looking at
the month rather than a setting about it, and a calendar that opens counting
entries has stopped being a calendar.

### CREATE — sessions are events, so they union

The fault the brief reported. `create_v1` travelled as one record and was chosen
between whole, so the newer device's copy **deleted** whatever the other one had
logged in between. Sessions and works both carry stable ids, so both now union
by id: the same session on both sides keeps the one with more hours on it (the
one still being added to), and a work keeps the one touched later, which is the
field CREATE already keeps for that question. Works are the same bug in the same
record, so they are fixed with it rather than left for the next report.

### The sync — there is no such thing as an overlap

The brief: *"it should know which one is the most recent and use that."* 4.13
made recency the rule but kept a sheet for the case with no most recent. That
case is now settled too:

1. the more recent record, where the journal knows both moments;
2. failing that, **the fuller one** — more fields written, and within a field
   more text (a field is worth 1 and text adds a fraction, so a longer note beats
   a shorter one and never beats a whole extra field);
3. failing even that, the two compared as text — arbitrary, but the *same*
   arbitrary answer on both devices, which is the only property that matters once
   nobody is being asked. Two devices disagreeing here would undo each other on
   every sync.

So the overlap sheet is **gone**: `syncOpen`, `syncPick`, `syncApply`,
`syncCancel`, the `#ovl` markup, the `.ovl-*` CSS and the `taken` argument to
`commit()`. `plan()` returns writes and notes.

### TOOLS — a correlations section

Between the bars and the split, over the series TOOLS already draws. Pearson on
the days where **both** series recorded something — a blank is not a zero here
any more than anywhere else in that file — in two shapes:

- **together**, same day: *sleep moves with mood*.
- **follows**, one day apart and computed both ways round: *at the desk tends to
  come before less energy*. It is the only relationship in the app that points
  one way rather than both.

Strongest first, six at most, each row carrying how strong it is, the r, and the
number of days behind it. Minimum six overlapping days, and below that it says
so instead of drawing a line. The heading says `not causes` and the wording is
"moves with" / "tends to come before", which are claims about numbers.
