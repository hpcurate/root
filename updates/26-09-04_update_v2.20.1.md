**Two items were underspecified and settled before starting:** "change logo"
meant CAL's wordmark, which becomes **DAY.**; and "the navigation" meant CAL's
day strip, not PLAN's due-date stepper.

## What was done

### 1. The wordmark → DAY

The tab wears **DAY.** and the nav caption says `day`. The app's id stays `cal`
everywhere it is an identity — `cal_days_v1`, `.ns-cal`, `Prefs.APPS`,
`appsSeen`, `data-panel="cal"` — because renaming that churns a storage key, a
namespace and the app migration for a word. Only labels moved: the wordmark,
the tab caption, `APP_NAMES`, `SEG_NAMES` and the storage report row. Same
split ROOT already keeps for `plan.types[].key`.

### 2. A task can take more than one block

`expSlots` maps a task to a **list** of slots rather than one. A job spanning
b1a and b1b is now one task given two hours instead of the same task sent and
picked twice.

- the description writes one line per slot — the same name twice, in the day's
  order, which is exactly what the downstream agent needs to build two events
- tapping a slot the task already holds gives back **that hour alone**
- a slot is still exclusive: another task asking for it is refused, by name
- the row says "2 slots" so a multi-hour job reads as deliberate
- DAY draws it as two blocks in the one project's colour

Everything that reads the assignment now takes `r.slots`, never `r.slot`.

### 3. The day is stepped, not scrolled

CAL's strip of day chips is replaced by ← and →, stepping through the days that
**exist** (the planned ones plus today) rather than the calendar, so "next"
never lands on a run of empty days. An arrow with nowhere to go is dimmed and
disabled *in place* — a control that vanishes at the edge shifts the label
beside it and the day jumps under your thumb.

A side benefit: the strip was a sideways scroller inside `#track`, which needs
its own `touch-action` to work under a finger at all. Two buttons and a label
need none of that.

### 4. Project tiles are one row

Half the height. Name and dot at the left, "3 sections" / "2 queued" at the
right end of the same row instead of underneath. `--tile-h` is 46px now, and
the open heading, the section rows and the task form were re-expressed in the
new unit so all three keep the exact height they had.

### 5. The transition stops being a zoom

Opening a project used to scale the tile into its heading — which scales its
border, its radius and its padding with it, and it was *only because the box
was being stretched* that its contents had to be held at `opacity:0` until the
scale resolved.

The box is not scaled any more. It is drawn at its new size, slid from its old
position, and its border and background **fade** between the two treatments.
`.proj-name` and `.proj-dot` carry their own flip keys and are FLIPped properly
— translated and scaled from where they were to where they are, never faded —
with `data-flip-text` naming their box so its slide is *subtracted* from theirs
rather than compounding with it.

This reverses a decision ROOT.md §6 recorded ("counter-scaling the children
does not work here"). That was true while the box itself was scaled; it is not
any more. The note was rewritten rather than deleted, with the reason kept.

### 6. DO's today list gets the blocks gesture

"→ tomorrow" turns the rows from tick to select, you pick what moves, one
button sends it, "all" is one tap. No longer gated on 20:00 — the old button
moved *everything* open, which only made sense late in the evening; choosing
what moves makes sense at any hour. A plant row is not selectable (TEND owns
those). `DO.deferToday()` called with nothing selected still moves every open
task, which is what it always did and what ROOT.md promised.

### 7. DAY reads lower case

`Prefs.formatDate()` is shared and capitalises, so it is folded in `cal.js`
rather than changed there. `.cw-date`, `.cw-rel` and `.ch-meta` set
`text-transform:none` **by name** — the one deliberate exception to ROOT's "a
new label says `var(--caps)`, never `uppercase`" rule, written into §9 so it
reads as a choice rather than a miss.
